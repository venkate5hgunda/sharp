# Real inference on CPU; offline contextual coaching in the app

`npm run eval:full` prefers WebGPU and automatically uses real CPU inference if browser GPU admission fails or the GPU test browser is absent. `eval:cpu` forces CPU; `eval:gpu` requires WebGPU and never falls back. A model-generation failure after successful GPU admission is not hidden by switching backends. CI runs the real suite, automatically using CPU on GPU-less runners. Portable unit tests and staged commit checks remain independent of model downloads; browser release enablement still requires GPU-specific evidence.

The CPU runner uses llama.cpp b11799 with **zero GPU layers**, the SmolLM2-360M-Instruct base model converted to Q4_K_M GGUF, 1,024-token context, greedy decoding and the same task prompts, schemas and validators. The CPU quantization/runtime is different from WebLLM's q4f16 build: CPU results establish inference behavior on the CPU artifact, not GPU compatibility or GPU performance. Both the official runtime archive and the immutable model revision are SHA-256 verified on each preparation. The runner supplies a fixed ChatML template instead of executing the model's embedded template.

The initial CPU package supports Linux x64 and requires Python 3.12+ for artifact preparation. It downloads a roughly 22 MB CPU runtime and 271 MB model on first use, caching them under ignored `.cache/sharp-evals/cpu/`. The server binds only to localhost, requires an ephemeral API token, serializes requests and is killed on completion. Model bytes, API tokens and browser profiles are never uploaded to Drive. Other CPU OS/architectures require separately pinned runtime packages; they fail explicitly rather than running fake inference.

The complete real suite runs 21 arithmetic and 81 contextual coach generations. CPU reports use `sharp-cpu-eval-v1`, `backend: cpu`, `source: model-cpu`, their own artifact identity and the exact source fingerprint. They are saved in `latest-cpu-report.json` before quality checks, so failures remain inspectable. They cannot pass the browser release recorder or release gate. Output correctness remains 100%, with zero fallbacks accepted and a ten-second task deadline. CPU p95 must be at most five seconds; the browser GPU budget remains three seconds. Shared-host CPU contention is measured against the CPU budget, never used to claim browser performance; CPU is not an excuse to substitute fixture outputs or accept bad results.

In the actual app, there is **no CPU model download**. A bundled repository provides 48 reviewed contextual lines for math, logic, reading, memory, focus, difficult rounds, progress, weekly achievements, settings and backups. It works offline and requires neither GPU nor network. Unsupported GPU admission uses this repository before any model download. Each automatic update is spaced at least **90 seconds** apart across contexts; recently used lines are avoided, and the panel never opens itself. Explicit encouragement requests can rotate immediately. Model-selected lines are also checked against recent model outputs to prevent immediate repetition. A context event during the cooldown preserves the current text; there is no periodic reminder timer.

Run `npm test`, `npm run test:browser` and `npm run eval:full` to validate the policy, UI and real inference separately. CPU success does not enable the public inference flag or qualify a browser/device.
